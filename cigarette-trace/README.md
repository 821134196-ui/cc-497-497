# 卷烟条包收货与退货追溯（演示系统）

门店按配送单接收卷烟条包，扫码记录品牌规格、条码、批次和库位；销售退回的条包
必须核对原始入库链路。破损、串码不符、重复扫描、非本店入库、超过退货期限分别
处置；已售条包不能被直接改回在库；退货由店员发起、店长复核、模拟配送方回执
决定是否最终出库。

**全部品牌与编号均为虚构演示数据。** 仅依赖 Python 3 标准库（`http.server` +
`sqlite3`），无第三方包、无需构建。

## 一条命令启动

```bash
./start.sh          # 默认 http://127.0.0.1:8000
./start.sh 8765     # 指定端口
```

## 五个页面

1. **收货扫描** `/receive.html`：扫描串码，固定显示完整串码与最近一次流转位置；
   与配送单核对品牌/条码/批次/库位；正常入库或异常隔离，重复/来源不明直接拦截。
2. **条包追溯** `/trace.html`：完整串码置顶固定；配送单原始记录与实物主档
   左右并排对比；append-only 流转时间线；店员在此发起退货（可传本地照片）。
3. **退货待审** `/returns.html`：店员只可查看；店长复核通过后可向模拟配送方
   索取回执，反复点击即**重放**（返回首次结论、不二次出库）。
4. **异常隔离** `/quarantine.html`：破损/串码不符/非本店等隔离条包，左右并排
   对比与文字处置结论；店长按规则处置；下方列出所有拦截留痕。
5. **库存差异** `/stock.html`：在库按品牌规格分组、可展开到一条条包；
   店长录入实盘数生成差异快照。

界面为浅灰底、低饱和红色提示；所有结论均以文字写明，颜色仅作辅助。

## 异常处置规则

| 场景 | 处置 |
|---|---|
| 破损 | 收货即隔离，不计在库，可走退货/报损 |
| 串码（条码/批次）不符 | 隔离，与配送单左右对比，核查后才能决定去向 |
| 重复扫描 | 拦截，不生成第二笔库存，仅留拦截事件 |
| 非本店入库 | 隔离，禁止转本店库存，只能拒收/转运 |
| 超过退货期限 | 发起退货即拦截（按配送单签收日 +30 天） |
| 已售退回 | 先进隔离核对入库链路；**任何环节都不能直接回在库**，配送方拒收也保留隔离 |
| 未售退货被驳回/配送拒收 | 核查后可以回到在库 |

## 关键约束如何保证

- **并发唯一性**：`packs.serial` 全库 `UNIQUE`，写操作经全局锁 +
  `BEGIN IMMEDIATE` 序列化；两人同时扫同一串码，一人成功、另一人被唯一约束拦截，
  库存只有一笔（见 16 线程并发测试）。
- **状态逆转拦截**：状态迁移走白名单 `ALLOWED_TRANSITIONS`，
  `SOLD` 的合法后继只有 `QUARANTINED`，没有任何路径能直达 `IN_STOCK`。
- **角色分离**：店员/店长按接口强制鉴权，跨门店操作同样拒绝。
- **回执幂等**：回执以申请为单位落库（稳定流水号），重放只追加
  `carrier_receipt_replay` 事件，不改库存状态。
- **每次流转留痕**：`flow_events` append-only；拦截类事件先随事务提交再返回
  错误，避免“拦截了但查无记录”。
- **照片在本地**：上传后写入 `data/photos/`，数据库只存路径。

模拟配送方规则：退货说明含 `@accept`/`@reject` 可指定结论；串码以 `X` 结尾
必判拒收；其余默认受理。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

35 个用例覆盖：并发射击同一串码的唯一性与 UNIQUE 兜底、SOLD→在库逆转拦截、
五类异常分流、店员/店长/跨店角色分离、回执首次/重放幂等，以及真实 HTTP
会话层（未登录、伪造 Cookie、端到端退货闭环）。

```
tests/                   unittest 测试
data/                    运行后生成：app.db、照片（git 忽略）
```
