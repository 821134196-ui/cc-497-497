# 门店卷烟条包流转追溯系统（演示）

按配送单接收卷烟条包，扫码记录品牌规格、条码、批次和库位；销售退回必须核对原始入库链路。
覆盖**收货扫描、条包追溯、退货待审、异常隔离、库存差异**五个页面。

> 所有品牌、条码、串码、门店、人员均为**虚构演示数据**；仅依赖 Python 3 标准库（含 sqlite3），无需安装任何第三方包、无需联网。

## 一条命令启动

```bash
./run.sh            # 首次自动建库、导入正常+异常串码，然后启动 http://127.0.0.1:8000
./run.sh --reset    # 清空 data/ 重新导入
PORT=8022 ./run.sh  # 换端口
```

等价的分步命令：

```bash
python3 -m app.cli init      # 建库 data/app.db + 照片 data/photos/，导入演示数据
python3 -m app.cli serve     # 启动 Web 服务
```

演示账号：

| 角色 | 账号 / 密码 | 权限 |
|---|---|---|
| 店员 | `clerk / clerk123`（一店） | 收货扫描、销售登记、发起退货 |
| 店长 | `manager / mgr123`（一店） | 退货复核、请求配送回执 |
| 二店店员 | `clerk2 / clerk123` | 用于验证“非本店入库 / 跨店不可见” |

## 五个页面

1. **收货扫描** — 按配送单扫码；顶部**固定栏始终显示完整串码、当前状态、最近一次流转位置**。
   异常结论下方以**左右并排**展示「系统预期 / 实际扫描」。底部是最近扫码记录（含被拒尝试）。
2. **条包追溯** — 输入完整串码，展示条包信息、入库→销售→退货→回执的**流转时间线**（每次流转一条 `flows` 记录）、退货单与配送回执。
3. **退货待审** — 店员发起退货（可传本地照片）；店长在队列中复核通过/驳回，再请求配送回执。
4. **异常隔离** — 破损、串码不符、非本店入库、配送拒收四类分列，文字结论 + 对比说明 + 本地照片。
5. **库存差异** — 库存按**规格分组**，点击行可展开到条包；下方按配送单逐行核对“应到/实到/在库/已售/出库/隔离/应到未扫”。

界面采用浅灰底、低饱和红色提示；所有结论均以**文字**表达（“正常 / 重复扫描 / 破损 / 串码不符 / 非本店入库 / 配送拒收…”），颜色仅作辅助，不靠颜色传递结论。

## 业务规则与处置分流

| 场景 | 处置 |
|---|---|
| 正常扫码 | 入库 `in_stock`，写收货流水，记录批次/库位 |
| 破损 | 勾选破损 → 直接 `quarantined`，不计在库，可附照片 |
| 串码不符 | 配送计划查无此码 / 条码与规格不符 / 属于本店别的配送单 → 隔离，留预期-实际对比 |
| 非本店入库 | 串码归属其他门店的配送单 → 隔离，记录归属门店 |
| 重复扫描 | 同串码再扫 → 拒绝并留痕，**不形成第二笔库存**；已隔离的码也不能借二次扫描“洗白” |
| 销售退回 | 必须是「已售」且存在**原始正常收货流水**，否则拦截 |
| 超期退货 | 售出超过 **7 天** → 系统直接拒绝并留审计记录，条包维持已售 |
| 店长驳回 | 条包**维持已售**，绝不回到在库 |
| 配送回执 | 接收 → 最终出库；拒收（批次争议等）→ 转异常隔离 |

**状态机（唯一合法流转，逆转一律拦截）：**

```
in_stock → sold → return_pending → return_approved → outbound
                     │ 驳回            │ 拒收
                     └→ sold           └→ quarantined（终态）
quarantined / outbound 为终态；不存在 sold → in_stock 的路径
```

并发保证：所有写操作在 `BEGIN IMMEDIATE` 事务内完成；`packages.code` 主键保证串码全局唯一，
`returns` 上“进行中退货”的部分唯一索引兜底——**两人并发扫同一串码只会形成一笔库存**。

## 模拟配送回执

`app/adapter_delivery.py` 为离线确定性适配器：串码在配送登记册内即接收；
批次争议清单中的串码（演示为 `YHY260004`）拒收。回执结果落 `receipt_log`，
对同一退货重复请求（重试/重放）直接读回原结果，**绝不重复出库**。

## 数据存储

- SQLite：`data/app.db`。核心表：`packages`（条包与状态）、`flows`（每次流转）、
  `scan_events`（每次扫码尝试，含被拒）、`returns`、`receipt_log`、`delivery_notes(_lines)`。
- 照片：`data/photos/`（种子生成 SVG 占位图；退货上传的照片 base64 解码后存本地）。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

21 个用例（`tests/test_core.py`）覆盖需求点：

- **唯一性**：`test_concurrent_same_code_single_stock`（双线程屏障并发，恰有一笔入库、一笔重复留痕）、
  `test_concurrent_return_requests`（并发退货仅一笔进行中）
- **状态逆转拦截**：`test_sold_cannot_be_set_back_to_in_stock`、`test_rejected_return_keeps_sold`、
  `test_quarantined_and_outbound_are_terminal`
- **角色分离**：店员不能复核/请求回执，店长不能发起，跨店不可操作
- **回执重放**：接收幂等、拒收维持结论、未复核不得请求回执
- **退货规则**：超 7 天拒绝、恰好 7 天放行、无入库链路拦截、非已售不可退
- **异常分流**：破损 / 串码不符 / 非本店 / 条码不符 / 异常码重复扫描不可洗白

## 目录结构

```
app/
  db.py                SQLite schema 与连接
  services.py          状态机与领域服务（收货/销售/退货/回执，全部事务化）
  queries.py           追溯、待审、隔离、库存分组、差异查询
  adapter_delivery.py  配送方模拟回执适配器
  seed.py              虚构演示数据（正常+异常串码、照片）
  server.py            标准库 HTTP：JSON API + 会话鉴权 + 静态页/照片
  cli.py               init / serve
web/                   五个页面（原生 HTML/CSS/JS，无依赖）
tests/                 unittest 用例
run.sh                 一条命令初始化并启动
```
